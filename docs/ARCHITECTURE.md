# Архитектура eBackup

Документ описывает устройство приложения на этапе v1 (вертикальный срез) и
зафиксированные проектные решения.

## Зафиксированные решения

| Тема | Решение |
|---|---|
| Платформа / стек | .NET 9 + C#; GUI — WinUI 3 (добавляется на UI-этапе) |
| Объём v1 | Вертикальный срез: локально + SFTP, модуль OBS, восстановление по манифесту, ручной запуск |
| Модули | Декларативный манифест (`*.module.json`) + опциональный код-хук |
| Шифрование | Опциональное (например, только при отправке на FTP/облако) |
| Секреты | Хранятся через Windows DPAPI / Credential Manager, не в открытом конфиге |

## Слои (проекты)

```
eBackup.Core            ← модель, движок, абстракции (ни от чего не зависит)
  ▲      ▲      ▲
  │      │      └── eBackup.Modules.Obs      (что бэкапить: OBS)
  │      └───────── eBackup.Storage.Local    (куда складывать: папка)
  │                 eBackup.Storage.Sftp     (куда складывать: SFTP — заглушка)
  └──────────────── eBackup.Cli              (точка входа, склейка)
eBackup.Tests          ← тесты на Core
eBackup.App  (позже)   ← WinUI 3 GUI поверх Core
```

### Ключевые абстракции (`eBackup.Core`)
- **`IBackupModule`** — описывает, *что* бэкапить. Метод `DiscoverAsync` возвращает
  список `PathEntry` (файлы/папки/ключи реестра). Это и есть «код-хук»: модуль
  может умно находить пути в рантайме.
- **`IStorageProvider`** — описывает, *куда* складывать готовый архив
  (`Upload`/`Download`/`List`). Провайдеров можно подключать несколько сразу.
- **`BackupEngine`** — собирает `.ebk` из модулей и распаковывает обратно.

## Формат архива `.ebk`

Это обычный **ZIP** со строгой структурой:

```
manifest.json          ← метаданные и карта путей (в корне)
data/
  obs/
    obs-studio/
      global.ini
      basic/...
```

- В `data/<archivePath>/...` лежат реальные файлы.
- Пути в манифесте — **токенизированные** (`{APPDATA}`, `{LOCALAPPDATA}`,
  `{PROGRAMFILES}`, `{PROGRAMDATA}`, `{USERPROFILE}`). См. `PathTokens`.
- **Шифрование (план):** готовый ZIP заворачивается в контейнер с AES-256-GCM,
  ключ выводится из парольной фразы через Argon2id; маленький незашифрованный
  заголовок хранит соль и параметры KDF.

### manifest.json
Пример — в [manifest.example.json](manifest.example.json). Поля:
- `formatVersion` — версия формата;
- `createdAt` — время создания (UTC);
- `source` — машина-источник (имя ПК, пользователь, версия ОС) для подсказок
  при восстановлении на другом железе;
- `modules[]` — по модулю: `moduleId`, `displayName`, `entries[]`;
- `entries[]` — `tokenPath`, `type` (`File`/`Directory`/`RegistryKey`),
  `archivePath`, `sha256` (для файлов).

## Восстановление
1. Прочитать `manifest.json`.
2. Для каждой записи развернуть `tokenPath` в реальный путь текущей машины
   (`PathTokens.Resolve`).
3. Если путь нестандартный/неизвестен (например, OBS установлен в другом месте) —
   *(план)* спросить пользователя / предложить переопределение.
4. Разложить файлы по местам согласно политике конфликтов
   (`ConflictPolicy`: `BackupExisting` по умолчанию → `Overwrite` → `Skip`).

## Модули

Модуль = **декларативный дескриптор** `*.module.json` (пути, маски, ключи
реестра) + **опциональный код-хук** (класс, реализующий `IBackupModule`) для
умного поиска.

Пример дескриптора OBS — `src/eBackup.Modules.Obs/obs.module.json`. Код-хук
`ObsBackupModule` сейчас отдаёт каталог `%APPDATA%\obs-studio`; позже добавим
автопоиск установки (реестр / процесс) и опциональные плагины.

## Состояние и дорожная карта

> Документ описывает ядро; актуальный обзор возможностей — в [README](../README.md).

**Сделано:**
- SFTP-хранилище целиком: провайдер на SSH.NET (upload/download/list/детальный
  листинг/delete/дерево папок/тест), учётки через DPAPI (`SftpConnectionStore`),
  приватный ключ хранится содержимым (зашифрован);
- опциональное шифрование архива (AES-256-GCM + Argon2id, чанки, заголовок `EBKE`);
- модульная система (гибрид): контракт `eBackup.Abstractions` (ApiVersion 1.0),
  `ModuleRegistry`, декларативные drop-in `*.module.json` с харднинг-валидацией,
  изоляция сбоев модулей, защита от zip-slip;
- модуль OBS: конфиг без кэшей, плагины из папки установки, внешние ассеты сцен
  с переписыванием путей при восстановлении (restore-хук с заужённым доступом);
- GUI на WinUI 3: Хранилища (master-detail, селф-тест ✓/✕), страница Бэкапа
  (модули + свои папки + цели + шифрование), Архивы (восстановление/удаление),
  Восстановление (в исходные места или папку, режимы конфликтов), Настройки
  (папка бэкапов, retention «хранить последних N» локально и на серверах);
- единая схема имён архивов (`BackupNaming`), прогресс-репортинг движка.

**Впереди:**
1. Экран «Модули» в GUI; живой дашборд «Обзора».
2. Иконка в трее; расписание (Планировщик Windows).
3. Бэкап ключей реестра; новые модули приложений.
4. Хранилища FTP и Google Drive (OAuth).
5. Динамические DLL-плагины — шаги 7–10 плана модульной системы
   (`.ebmod`, AssemblyLoadContext с делегированием контракта, TrustStore/подписи).
6. **Установщик:** один пакет (`eBackup-setup.exe`, Inno Setup/WiX); приложение
   собирается self-contained, чтобы у пользователя не требовался установленный .NET.
7. Анимации интерфейса; логотип (рисует художница).
