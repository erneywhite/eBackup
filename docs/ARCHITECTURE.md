# Архитектура eBackup

Документ описывает устройство приложения и зафиксированные проектные решения.

## Зафиксированные решения

| Тема | Решение |
|---|---|
| Платформа / стек | .NET 9 + C#; GUI — WinUI 3 (unpackaged, self-contained WindowsAppSDK) |
| Модули | Декларативный манифест (`*.module.json`) + опциональный код-хук; контракт заморожен в `eBackup.Abstractions` (ApiVersion 1.0, append-only) |
| Хранилища | Единая модель `SavedStorage`/`IArchiveStorage`: 8 типов одновременно |
| Шифрование | Опциональное: AES-256-GCM по чанкам + Argon2id (заголовок `EBKE`); через службу — разовый тикет фразы (интерактив) или машинный ключ (расписания), fail-closed |
| Секреты | Windows DPAPI (CLI/локально) и **машинный ключ** службы (ProgramData, AES-256-GCM под DPAPI-LocalMachine — чтобы расписания расшифровывали без вошедшего пользователя); в открытом конфиге не лежат и не переносятся на другой ПК |
| Служба / IPC | Привилегированная работа в фоновой службе **LocalSystem**; GUI — тонкий клиент через named-pipe (framed JSON, контракт в `eBackup.Ipc`); решения по доступу — по OwnerSid вызывающего |

## Слои (проекты)

```
eBackup.Abstractions    ← замороженный контракт плагинов (интерфейсы, манифест)
  ▲
eBackup.Core            ← движок (+верификация), крипто, реестр модулей,
  ▲   ▲   ▲   ▲            расписания, журнал «Истории»
  │   │   │   └── eBackup.Modules.Obs   (что бэкапить: OBS)
  │   │   └────── eBackup.Storage       (куда: папки/SMB, FTP, S3, WebDAV,
  │   │                                  GDrive, Dropbox, MEGA; seek-чтение кусками)
  │   │           eBackup.Storage.Sftp  (SFTP на SSH.NET)
  │   │           eBackup.Storage.Local (базовый локальный провайдер)
  │   └────────── eBackup.Security      (DPAPI + машинный ключ службы)
  │
  ├── eBackup.Service ← хост LocalSystem: исполняет бэкап/restore/историю/архивы/
  │     ▲               модули/расписания с нужными правами и без входа в систему
  │     │ named-pipe (eBackup.Ipc: framed JSON, контракт + транспорт)
  │     ▼
  ├── eBackup.App     ← WinUI 3 GUI — тонкий клиент службы
  └── eBackup.Cli     ← консоль (на едином локальном сторе)
eBackup.Tests          ← тесты
```

### Ключевые абстракции (`eBackup.Abstractions`)
- **`IBackupModule`** — описывает, *что* бэкапить. Метод `DiscoverAsync` возвращает
  список `PathEntry` (файлы/папки/ключи реестра). Это и есть «код-хук»: модуль
  может умно находить пути в рантайме.
- **`IArchiveStorage`** (в `eBackup.Storage`) — *куда* складывать
  (`Upload`/`Download`/`ListDetailed`/`Delete`/`Test`); целей может быть много
  сразу. `ISeekableArchiveStorage` дополнительно отдаёт удалённый архив как
  поток с произвольным доступом.
- **`BackupEngine`** — собирает `.ebk` из модулей, верифицирует и
  распаковывает обратно (включая выборочное восстановление по фильтру).

## Формат архива `.ebk`

Это обычный **ZIP** со строгой структурой:

```
manifest.json          ← метаданные и карта путей (в корне)
data/
  obs/
    obs-studio/
      global.ini
      basic/...
```

- В `data/<archivePath>/...` лежат реальные файлы.
- Пути в манифесте — **токенизированные** (`{APPDATA}`, `{LOCALAPPDATA}`,
  `{PROGRAMFILES}`, `{PROGRAMDATA}`, `{USERPROFILE}`). См. `PathTokens`.
- **Шифрование:** готовый ZIP заворачивается в контейнер с AES-256-GCM
  (чанки по 1 МиБ), ключ выводится из парольной фразы через Argon2id;
  маленький незашифрованный заголовок `EBKE` хранит соль и параметры KDF.

### manifest.json
Пример — в [manifest.example.json](manifest.example.json). Поля:
- `formatVersion` — версия формата;
- `createdAt` — время создания (UTC);
- `source` — машина-источник (имя ПК, пользователь, версия ОС) для подсказок
  при восстановлении на другом железе;
- `modules[]` — по модулю: `moduleId`, `displayName`, `entries[]`;
- `entries[]` — `tokenPath`, `type` (`File`/`Directory`/`RegistryKey`),
  `archivePath`, `sha256` (для файлов).

## Восстановление
1. Прочитать `manifest.json`.
2. Для каждой записи развернуть `tokenPath` в реальный путь текущей машины
   (`PathTokens.Resolve`).
3. Если путь нестандартный/неизвестен (например, OBS установлен в другом месте) —
   *(план)* спросить пользователя / предложить переопределение.
4. Разложить файлы по местам согласно политике конфликтов
   (`ConflictPolicy`: `BackupExisting` по умолчанию → `Overwrite` → `Skip`).

## Модули

Модуль = **декларативный дескриптор** `*.module.json` (пути, маски, ключи
реестра) + **опциональный код-хук** (класс, реализующий `IBackupModule`) для
умного поиска.

Пример дескриптора OBS — `src/eBackup.Modules.Obs/obs.module.json`. Код-хук
`ObsBackupModule` сейчас отдаёт каталог `%APPDATA%\obs-studio`; позже добавим
автопоиск установки (реестр / процесс) и опциональные плагины.

## Состояние и дорожная карта

> Документ описывает ядро; актуальный обзор возможностей — в [README](../README.md).

**Сделано:**
- **единая модель хранилищ** (`eBackup.Storage`): 8 типов — папка/сетевой диск
  (SMB-креды через WNetAddConnection2), SFTP (SSH.NET, ключ содержимым), FTP/FTPS
  (FluentFTP), S3-совместимые (AWSSDK), WebDAV (чистый HttpClient), Google Drive и
  Dropbox (OAuth: PKCE + loopback-редирект, refresh-токены в DPAPI), MEGA (вход один раз
  с 2FA → сохранённая сессия, дальше без пароля/2FA); общий `IArchiveStorage`,
  `StorageFactory`, селф-тесты;
- **чтение удалённых архивов кусками** (`ISeekableArchiveStorage`): SFTP-seek и
  HTTP Range через буферизованный `RangeStream` — браузер архива открывает
  оглавление 100-гигового облачного архива за секунды и тянет только выбранное;
- опциональное шифрование архива (AES-256-GCM + Argon2id, чанки, заголовок `EBKE`);
- **верификация каждого бэкапа**: полная перечитка ZIP (CRC32) + сверка SHA-256
  с манифестом до отправки; на целях — контроль размера, для папок — SHA-256 копии;
- модульная система (гибрид): контракт `eBackup.Abstractions` (ApiVersion 1.0),
  `ModuleRegistry`, декларативные drop-in `*.module.json` с харднинг-валидацией,
  изоляция сбоев модулей, защита от zip-slip; выборочное восстановление
  (`entryFilter`) для браузера архива;
- модуль OBS: конфиг без кэшей, плагины из папки установки, внешние ассеты сцен
  с переписыванием путей при восстановлении (restore-хук с заужённым доступом);
- **расписания**: daily / weekly (дни недели) / каждые N часов / раз в день при
  простое ПК (`IdleDetector` + `SystemLoadMonitor`), окно допуска 30 мин без
  «догона», свои настройки у каждого расписания, «Выполнить сейчас»;
- **журнал «История»** (`Core/History`): запись о каждой операции (бэкап /
  восстановление / извлечение) + полный лог с таймкодами (каждый файл, скорости,
  верификация); детальный лог-канал движка (`Action<string> log`);
- GUI на WinUI 3 целиком: Обзор-дашборд (занятое место, статусы), Бэкап,
  Хранилища (7 редакторов, OAuth-вход через браузер), Архивы + браузер архива
  (дерево с галочками: восстановить выбранное / скачать), Восстановление,
  Расписание, История, Настройки (сжатие, имя ПК в имени, папка ассетов,
  retention, интервал проверок, очистка temp, «купить кофе»);
- трей + автозапуск, уведомления о результатах, проверка свободного места до
  бэкапа, «жидкий» прогрессбар (пружинная модель воды), направленные переходы
  вкладок, фирменный логотип;
- единая схема имён архивов (`BackupNaming`, опц. имя ПК), CLI на едином сторе;
- **установщик** (`installer/eBackup.iss`, Inno Setup, self-contained publish,
  ассоциация `.ebk`, автозапуск, тихая установка из апдейтера) и **автообновление**
  через GitHub Releases (`UpdateService`); релизы v0.1.0 → v1.1.0 опубликованы.

**Сделано в 1.1:** каталог модулей (репо `catalog/` + сервис с кэшем/оффлайном +
UI «Модули→Каталог» + установка в один клик + фильтр), отмена бэкапа (CancellationToken),
корзина модулей, retention по группам модулей, устойчивость движка (пропуск нечитаемых
файлов + warn-статус), модули SSH/VS Code, источник модулей без рамок app-data.

**Сделано в 1.2 (релиз v1.2.0):** фоновая служба Windows (**LocalSystem**) — бэкап,
восстановление, история, архивы, модули и расписания исполняются службой с нужными
правами и **без входа в систему**; GUI — тонкий клиент по named-pipe (`eBackup.Ipc`,
framed JSON, source-gen JSON-контекст, доступ по OwnerSid); секреты и расписания — под
**машинным ключом** в ProgramData; **шифрование через службу** (разовый тикет фразы для
интерактива, машинный ключ для расписаний, пост-проверка расшифровкой, fail-closed);
8-е хранилище **MEGA** (вход один раз с 2FA → сохранённая сессия).

**Впереди:**
1. Динамические DLL-плагины — шаги 7–10 плана модульной системы
   (`.ebmod`, AssemblyLoadContext с делегированием контракта, TrustStore/подписи).
2. Бэкап ключей реестра Windows.
3. English UI.
4. Выборочное чтение зашифрованных архивов без полного скачивания
   (формат `EBKE` чанковый — случайный доступ возможен).
